# dsh-lazy-toolbox 介绍（中文）

> DeepSeek Harness 插件。把 skill 与 MCP 从「每轮对话都塞进工具定义」改成「列个目录，用时才注入」。
> 仓库：<https://github.com/anyi-520/dsh-lazy-toolbox>

## 一句话

DSH 每发一次请求，都会把「我会用的所有工具」的说明书一起带上。工具一多，这份说明书就变成
几万甚至几十万 token 的常驻开销；这个插件把说明书从桌上拿下来，换成一个随身工具箱：
平时只留一把螺丝刀（`toolbox` 这一个工具），要用锤子时再把它递到你手里，用完收回去。

## 为什么需要它（真实数字）

拿 REA（逆向工程 MCP，207 个工具）实测，同样是「全在上下文里」的两种口径：

| | 工具数 | 工具定义体积 | 约等于 token |
| --- | --- | --- | --- |
| 不用插件，全量常驻 | 207 | 385,025 字符 | ≈ 110,000 |
| 用插件，按需注入 3 个 | 3 | 3,121 字符 | ≈ 892 |

省 99%。省下来的不只是钱，还有模型挑错工具的概率——207 个工具里挑一个，
和「目录里写着用哪几个」再挑，难度完全不是一回事。

## 它具体做了什么

| 能力 | 说明 |
| --- | --- |
| 目录化 | 系统提示里只放一份「一句话用途」清单：`skill:xxx — 干什么用的`，不含任何参数 |
| 按需注入 | `toolbox { action: "load", ids: ["mcp:rea:binary_overview"] }` 只注入你要的那几个 |
| 用完卸载 | `unload`，或回合结束自动卸（`autoUnloadOnTurnEnd`），工具定义还回去 |
| 只在当前会话 | 注入的是 agent 作用域的工具表，别的会话看不到，DSH 自己的配置不被改 |
| 新会话不迷路 | 每个新对话的运行时上下文里会提醒「本机还有 N 个 skill、M 个 MCP，不在工具列表里」 |
| 设置页开关 | `设置 → 懒工具箱`：每条一个开关。关掉 = 不进目录、不许加载，文件还在 |
| 搬家 + 还原 | 安装时把散在各处的 skill / MCP 收进库里；卸载时原样还回去（`restore`） |
| 插件内置资产自动接管 | 插件自带的 `skills/`、`mcp.json`、`dsh.skills` / `dsh.mcp` 会自动登记（原地引用，不复制） |
| 本地运行日志 | `logs/plugin-YYYYMMDD.log`，JSONL，记录每一次调用与错误堆栈；设置页不显示 |
| 零依赖 | 自己实现 MCP 客户端、YAML 子集解析、schema 规范化，装进 profile 不需要额外依赖 |

## 一次完整的用法（真实流程）

你说：「你有懒工具箱吧？用 rea 看看 `D:\samples\a.exe` 是什么。」

1. 模型看到目录：`mcp:rea — REA：逆向一切（207 个 MCP 工具）…`
2. 它自己决定要哪几个，调 `toolbox { action: "load", ids: ["mcp:rea:open_binary", "mcp:rea:binary_overview", "mcp:rea:list_procedures"] }` → 只注入 3 个定义
3. 干活：`open_binary` 给出 `pe / x86_64 / sha256 …`；`binary_overview` 让 Ghidra 真跑一遍，
   报出 9 个段、198 个函数、153 个字符串；`list_procedures` 列出入口点与导入表
4. 收工：`toolbox { action: "unload", all: true }`，上下文回到干净状态

## 装法

```bash
git clone https://github.com/anyi-520/dsh-lazy-toolbox.git
node dsh-lazy-toolbox/bin/cli.mjs wire-profile   # 建链接 + 写 cordis.patch.yml + 补 client 声明
# 重启 DSH → 设置 → 懒工具箱
```

也可以下载 [Release 附件](https://github.com/anyi-520/dsh-lazy-toolbox/releases/latest) 解压后执行同一条命令。

## 常用命令

```bash
node bin/cli.mjs status                # 库里有什么
node bin/cli.mjs list                  # 目录（一句话用途）
node bin/cli.mjs discover --dry-run    # 看看已装插件里有哪些内置 skill / MCP
node bin/cli.mjs enable skill:<名字>    # 打开（等同设置页开关）
node bin/cli.mjs disable mcp:<服务>     # 关闭：不进目录、不能加载，文件还在
node bin/cli.mjs logs --lines 50       # 本地运行日志
node bin/cli.mjs doctor                # 自检
```

## 边界与取舍

- **不碰 DSH 自己的配置**（除了 `wire-profile` 那条安装行），注入只发生在 agent 作用域；
- 卸载时把安装时搬走的文件**原样还回去**，不留残骸；
- 插件内置的 skill **原地引用**，插件升级后内容自动是新的，库里不会留旧副本；
- 需要 DSH Desktop ≥ 0.2.1-rc.5、Node ≥ 20；测试 51 项全绿。

## 目录结构

```
lib/index.js      注册 toolbox、目录 section、HTTP 端点、生命周期钩子
lib/tools.js      常驻工具的动作实现
lib/inject.js     按会话注入 / 卸载
lib/discover.js   插件内置 skill / MCP 的发现与接管
lib/skills.js     skill 发现、搬入、加载、还原
lib/migrate.js    迁移与还原（MCP 行 + skill 目录）
lib/store.js      库文件 store.json + skills/
lib/log.js        本地 JSONL 运行日志
client.js         设置页「懒工具箱」那一节（浏览器半）
test/             51 项 node:test
```
