# 群友上手（3 分钟）

> `dsh-lazy-toolbox` — 把 skill 与 MCP 从**默认工具定义**里抽出来，改成用时热加载、用完卸载。
> 目的很简单：DSH 每次请求都会把工具定义带上，一个 200 工具的 MCP 服务就能吃掉几万 token；
> 现在默认只有 1 个 `toolbox` 工具，其余按需注入。

## 一、它解决什么

| 不装 | 装了 |
| --- | --- |
| MCP 的 207 个工具定义（几十 KB schema）每轮都在上下文里 | 平时只有 `toolbox` 一个工具；需要用时注入 1~3 个 |
| 工具一多，模型容易选错工具 | 系统提示里只有一份「一句话用途」目录，模型自己挑 |

实测：REA（207 个工具）从「全量常驻」变成「按需注入 3 个」后，单轮请求体积降了一个数量级。

## 二、装法（任选）

### A. 直接从本地目录接（最简单，不用发 npm）

1. 解压到任意目录，例如 `D:\dsh-lazy-toolbox`
2. 在 profile 里挂一个链接（Windows 用 junction，不需要管理员）：

```powershell
$profile = "$env:USERPROFILE\.dsh\profiles\desktop"
New-Item -ItemType Junction -Path "$profile\node_modules\dsh-lazy-toolbox" -Target "D:\dsh-lazy-toolbox"
```

3. 在 `$profile\cordis.patch.yml` 里加一行（缩进按你文件里已有的行来）：

```yaml
- id: lazy-toolbox
  name: dsh-lazy-toolbox
  inject: [systemPrompt, tools, webServer]
```

4. 重启 DSH。
5. 打开 `设置 → 懒工具箱`，能看到 skill / MCP 的开关面板就算成功。

### B. npm 装（发布后）

```bash
dsh plugin add dsh-lazy-toolbox
```

## 三、装完怎么用

问 AI 一句话就行：

> 「你有懒工具箱吧？把 rea 里跟 PE 有关的工具加载一下，分析 `D:\samples\a.exe`」

AI 会走 `toolbox { action: "load", ids: ["mcp:rea:binary_overview"] }`，注入完立刻能调用；
用完 `toolbox { action: "unload", all: true }` 还回去（回合结束也会自动卸）。

设置页里还能单独关掉某个 skill / MCP：**关掉 = 不进目录、不许加载，但文件不删**，
想恢复点一下开关就行。

## 四、命令行

```bash
node bin/cli.mjs status      # 库里有什么
node bin/cli.mjs list        # 目录（含一句话用途）
node bin/cli.mjs logs        # 本地运行日志（最近 100 条）
node bin/cli.mjs doctor      # 自检：数据目录 / 链接 / 版本
```

## 五、日志在哪（报 bug 请贴这个）

```
%USERPROFILE%\.dsh\lazy-toolbox\logs\plugin-YYYYMMDD.log
```

一行一条 JSON，含 `toolbox.call`（动作、耗时、成功与否、失败堆栈）、`inject.load`、
`mcp.connect`、`api.request` 等。**只写本地文件**，不上报。

出问题时把 `logs` 目录里当天那个文件发出来即可，敏感内容请先自己看一眼（命令里可能带路径）。

## 六、已知边界

- 只在 **当前会话** 注入，不污染别的会话，也不改 DSH 自己的配置；
- 卸载 MCP / skill 时会把安装时搬走的文件**原样还回去**（`node bin/cli.mjs restore`）；
- 客户端设置页需要 DSH 启动时扫描到 `package.json` 里的 `dsh.client`，**改完 client.js 必须重启**（刷新页面不够）；
- 需要 DSH Desktop ≥ 0.2.1-rc.5、Node ≥ 20。
